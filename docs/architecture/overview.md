# Overview

```text
entries/*.toml ──┐
                 ├─ angelica map verify (game executable) ──> builds/<version>.toml
map.toml ────────┘                                                │
                                                                  ▼
                                               signed map feed ──> Angelica host in the game
```

## Layout

- `map.toml`: the format version.
- `entries/<area>.toml`: entries of one area; see [`naming.md`](./naming.md).
- `builds/<game version>.toml`: one build record per game executable, generated by `angelica map verify`.
- `THIRD_PARTY_NOTICES.md`: license notices of imported data, added with the first imported entry.

## The `angelica` tool version

`tool.toml` pins the `angelica` commit whose `angelica map verify` produces the build records. A build record names the map it was produced from by its `entries_sha256`. Changing the pinned commit regenerates every build record that is still published.

## Publication

A release tag on `main` publishes the map ([releases](../development/releases.md)): the entries and the build records of the supported game versions are packed, signed, and served as a feed that the host checks 20 seconds after the game starts and every hour. A merge alone publishes nothing. The host uses a published build record for the running executable when one exists; otherwise it resolves entries itself, as described in the `angelica` repository ([game map resolution](https://github.com/AngelicaProject/angelica/blob/main/docs/architecture/game-map.md)).
